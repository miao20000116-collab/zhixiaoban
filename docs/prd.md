## 1.2 项目背景

随着就业市场竞争加剧，求职用户在寻找工作过程中面临越来越复杂的问题。从岗位选择、简历准备，到面试训练、职业决策，整个求职过程涉及大量信息收集、内容准备和持续优化工作。

目前市场上的求职辅助工具主要集中于单点能力，例如简历生成、JD匹配、面试题生成等，但这些产品通常存在以下问题：

第一，工具之间相互割裂。用户需要在多个产品之间切换，例如使用一个工具修改简历，另一个工具准备面试，再使用搜索工具了解公司和行业信息，无法形成完整的求职闭环。

第二，AI缺少对用户长期背景的理解。传统AI助手通常只基于当前一次对话生成内容，无法持续理解用户的职业经历、优势能力、目标岗位以及历史求职表现，因此无法提供个性化建议。

第三，求职过程不仅包含信息和能力问题，也包含长期心理压力。用户在求职过程中会经历投递无反馈、面试失败、自我怀疑、Offer选择困难等情况，目前大部分求职工具无法提供持续性的陪伴和反馈。

因此，本项目希望构建一个面向求职用户的 AI 求职伙伴，通过多 Agent 协作、用户职业记忆、岗位分析、面试训练和智能评估能力，覆盖用户从求职准备到获得 Offer 的完整流程。

## 1.3 产品定位

AI求职辅助 Agent 是一个面向广大求职用户的智能求职助手。

产品定位：

> 一个能够理解用户职业背景、分析目标岗位、辅助生成求职材料、模拟真实面试，并持续帮助用户提升求职能力的 AI 求职伙伴。

产品不是单纯的内容生成工具，而是通过长期记忆和多 Agent 协作，为用户提供持续性的求职支持。

# 二、需求分析

## 2.1 业务背景

随着就业市场竞争不断加剧，求职用户在寻找工作的过程中，需要处理大量复杂任务，包括岗位筛选、公司研究、简历准备、面试训练、职业决策等。

传统求职流程通常依赖用户自主完成：

- 浏览招聘网站寻找岗位；
- 阅读JD判断岗位要求；
- 修改简历匹配岗位；
- 搜索公司和行业信息；
- 自己准备面试问题；
- 通过多次失败总结经验。


这一过程存在明显的问题：

第一，求职流程复杂且分散。

用户需要使用多个工具完成不同任务：

例如：

- 简历工具负责修改简历；
- 搜索工具负责了解公司；
- ChatGPT负责生成面试题；
- 视频工具负责练习表达。

不同工具之间没有共享用户信息，导致用户需要重复输入自己的经历和目标。

---

第二，AI工具缺少长期用户理解能力。

当前大部分 AI 求职产品仍然基于单次对话模式。

用户每次使用时，都需要重新输入：

- 工作经历；
- 项目背景；
- 目标岗位；
- 面试情况。

AI无法形成完整的用户职业画像。

例如：

用户第一次告诉AI：

“我过去负责用户增长。”

第二次进行面试模拟时：

AI并不知道用户有哪些增长项目，也无法针对这些项目进行深度追问。

---

第三，岗位分析深度不足。

目前很多 JD 分析工具主要完成：

- 提取关键词；
- 总结岗位职责；
- 匹配技能。


但是实际求职过程中，用户真正需要的是：

> “这个岗位为什么需要这些能力，以及面试官会如何考察。”

例如：

JD中写：

“负责AI产品设计。”

普通工具可能输出：

“需要懂AI产品。”

而专业求职助手应该进一步分析：

- 该岗位可能关注AI应用落地能力；
- 需要理解LLM、RAG、Agent等技术边界；
- 面试可能考察AI方案设计和模型效果评估。

---

第四，求职过程存在明显情绪压力。

求职周期通常较长，用户会经历：

- 长时间没有面试机会；
- 多次面试失败；
- 对自身能力产生怀疑；
- 不知道下一步提升方向。


当前求职工具主要解决“事情”，但无法解决“过程”。

因此，需要一个能够长期理解用户状态，并提供基于数据反馈和事实分析的 AI 求职伙伴。

# 2.5 为什么采用 Agent 架构

传统 Chatbot 主要依赖单模型完成所有任务。

但是求职场景具有明显复杂性：

不同任务需要不同能力。

例如：

| 任务 | 所需能力 |
| ---- | ---- |
| JD分析 | 行业理解、岗位分析 |
| 简历优化 | 文案能力、经历理解 |
| 面试模拟 | 对话控制、追问能力 |
| 技术问答 | 专业知识理解 |
| 质量检查 | 内容审核、真实性判断 |

如果所有任务交给一个模型，会出现：

- 角色混乱；
- 输出质量不稳定；
- 难以控制任务边界。


因此采用：

> 主控 Agent + 专业 Agent + Memory + Evaluation 的架构。


整体：

```
用户

↓

主控Agent

↓

任务识别

↓

调用专业Agent

↓

质量评估

↓

输出结果

↓

更新用户记忆

```

# 3.3 聊天系统设计

## 3.3.1 功能定位

聊天系统是用户唯一入口。

产品不采用传统工具导航模式，而采用类似 ChatGPT / 豆包的对话模式。

用户无需提前选择：

“我要使用简历功能。”

而是直接表达需求。

例如：

用户：

> 帮我看看这个岗位适不适合我。

系统自动判断：

需要调用：

- JD分析；
- 用户画像；
- 岗位匹配。


---

# 3.3.2 多窗口对话设计

用户可以创建多个独立聊天窗口。

但是：

窗口不是任务绑定关系。

即：

不是：

一个JD = 一个窗口。

而是：

一个窗口 = 一个用户自主管理的对话空间。

---

例如：


- JD分析；
- 面试题；

- 简历修改。


窗口2：

```
简历优化
```

包含：

- 经历整理；
- STAR生成。


---

两个窗口：

上下文独立。

但是：

共享职业记忆。

```text id="6zyy0s"
       ↓
```

# 3.9 Evaluation 系统设计

## 3.9.1 功能定位

Evaluation 系统是 AI 求职辅助 Agent 的质量控制层。

由于产品涉及：

- 简历生成；
- 项目经历包装；
- 岗位分析；
- 面试评价；
- 职业建议；

这些内容均属于影响用户求职结果的高价值信息，因此需要对 AI 输出进行持续评估和校验。

Evaluation 系统不直接面向用户提供功能，而是作为所有 Agent 的基础能力，为 AI 输出提供：

- 真实性检查；
- 岗位匹配检查；
- 内容质量评价；
- 信息可信度检查。

整体流程：

```text
用户需求

↓

业务Agent处理

↓

生成结果

↓

Evaluation检查

↓

通过

↓

返回用户

```

---

# 3.9.2 Evaluation 系统架构

整体分为四层：

```text
                 Evaluation System


------------------------------------------------

真实性评估

防止AI虚构用户经历


岗位匹配评估

判断内容是否符合目标岗位


质量评估

判断回答和内容质量


信息可信度评估

判断外部信息可靠性


------------------------------------------------

```

---

# 3.9.3 真实性评估

## 功能目标

防止 AI 在优化简历、生成项目经历时产生虚假内容。

这是求职场景中最重要的质量控制能力。

---

## 典型问题

用户：

> 我参与过客服流程优化。


AI生成：

> 主导建设千万级智能客服系统，实现服务效率提升30%。

存在风险：

1. 用户没有说明负责范围；
2. 数据指标不存在；
3. 职责等级被扩大。

---

## 检查流程

输入：

```text
用户职业档案

+

AI生成内容

```

Evaluation 判断：

```text
是否新增：

- 未出现的项目经历
- 未提供的数据指标
- 未承担的职责
- 未拥有的技能

```

---

输出：

例如：

```json
{
"risk_level":"high",

"problem":

"主导建设智能客服系统未经用户确认",

"suggestion":

"修改为参与客服流程优化"

}

```

---

# 3.9.4 岗位匹配评估

## 功能目标

判断 AI 输出是否真正服务于目标岗位。


例如：

用户目标：

AI产品经理。


AI优化后的简历：

大量强调：

活动运营。

虽然内容正确，但是岗位匹配度低。


---

检查维度：

| 维度 | 检查内容 |
|-|-|
| 技能匹配 | 是否覆盖岗位核心能力 |
| 经历匹配 | 是否突出相关项目 |
| 关键词匹配 | 是否包含岗位关注内容 |
| 能力表达 | 是否体现岗位要求 |

---

输出：

```text
岗位匹配度：

78分


优势：

具备用户增长经验


不足：

缺少AI产品相关经历表达


建议：

增加AI项目设计和技术理解内容

```

---

# 3.9.5 面试回答质量评估

主要服务：

面试训练 Agent。


评价维度：

## 1. 问题理解能力

是否准确理解面试官问题。

---

## 2. 回答结构

是否符合：

结论 → 原因 → 案例 → 结果。


---

## 3. 专业能力

是否体现：

岗位要求能力。


---

## 4. 表达能力

包括：

- 是否清晰；
- 是否冗余；
- 是否逻辑混乱。


---

## 5. 岗位匹配度

回答是否符合目标岗位。

---

示例：

```text
回答评分：

82分


优势：

项目背景描述清晰


问题：

缺少业务结果说明


优化建议：

补充项目影响和量化指标

```

# 4.2 Multi-Agent架构设计

## 4.2.1 为什么采用Multi-Agent

求职场景具有高度复杂性。

一个用户需求可能同时包含：

例如：

> 我要准备腾讯AI产品经理面试，帮我看看我的经历够不够。

2. 分析用户经历；

4. 生成面试计划。


单一模型很难稳定处理。


因此拆分专业 Agent：

每个 Agent 聚焦自己的任务。

# 五、Prompt工程设计

# 5.1 Prompt工程整体设计目标

AI求职辅助 Agent 中，不同任务对模型能力要求不同。

例如：

| 场景 | 核心能力 |
|----|----|
| JD分析 | 信息理解、行业分析、岗位推理 |

| 情绪陪伴 | 用户状态理解 |

系统采用：

> System Prompt + Task Prompt + Context Prompt + Memory Prompt + Output Constraint

组合方式。


# 十五、Agent详细技术规格设计

# 15.1 Agent整体设计原则

AI求职辅助 Agent 采用：

> 专业 Agent 分工 + Master Agent统一调度。

每个 Agent 只负责明确领域任务。

避免：

一个 Agent 同时负责：

- 简历；
- 面试；
- 行业分析；
- 情绪陪伴。


导致：

- Prompt复杂；
- 输出不稳定；
- 难以优化。

```text id="agent001"

                    Master Agent


                          ↓


------------------------------------------------


Resume Agent

Job Intelligence Agent

Interview Agent

Career Agent

Evaluation Agent

Memory Agent


------------------------------------------------


Tools:

Search

RAG

File Parser

ASR


```

传统产品可以通过行为判断用户满意度。

例如：

点击。

停留。

转化。


但是 AI 产品存在：

“用户看起来使用了，但是不知道结果是否有价值。”

例如：

用户生成了一份简历。

但是：

- 是否真的采用？
- 是否帮助获得面试？
- 是否觉得AI可信？


因此需要主动收集反馈。

---

# 16.3.2 反馈入口设计

反馈不应该设计成：

“请评价本次回答。”

这种太打扰。


应该嵌入关键节点。


---

## 场景1：简历优化完成后

AI：

> 这版简历是否符合你的预期？

按钮：

- 有帮助
- 需要修改


---

## 场景2：面试复盘结束

AI：

> 这次反馈是否帮助你发现问题？


---

## 场景3：JD分析完成

AI：

> 岗位分析是否帮助你判断是否值得投递？


---

# 16.4 Agent效果监控体系

AI产品必须监控每个Agent。


---

# 16.4.1 Master Agent监控

关注：

## 意图识别准确率

例如：

用户：

> 分析一下这个岗位。

是否正确进入：

Job Agent。


---

## Agent路由错误率

例如：

应该调用Resume Agent。

错误调用Interview Agent。


---

指标：

```text id="op005"

Routing Accuracy

=

正确调用次数

/

总请求次数

```

目标：

> ≥95%

---

# 16.4.2 Resume Agent监控

关注：

## 简历修改采纳率

不是：

AI生成了多少字。


而是：

用户是否采用。


---

指标：

```text id="op006"

Resume Adoption Rate

=

用户保存优化版本次数

/

简历优化次数

```

---

## 真实性风险

监控：

- 虚构经历；
- 虚构指标；
- 夸大职责。


---

# 16.4.3 Job Agent监控

关注：

## 岗位分析有效性。


例如：

用户分析岗位后：

是否继续：

- 修改简历；
- 开始面试训练；
- 收藏岗位。


---

指标：

岗位分析后的下一步转化率。

---

# 16.4.4 Interview Agent监控

重点：

## 面试训练价值。


指标：

### 训练次数

用户是否持续训练。


---

### 能力提升趋势

例如：

第一次：

65分。


第五次：

80分。


---

### 用户复用率

完成一次模拟后：

是否再次使用。


---

# 16.5 Prompt优化体系

这是 AI 产品经理的重要工作。

Prompt不是开发完成后固定。


需要：

持续优化。


---

# 16.5.1 Prompt优化流程

```text id="op007"

发现问题

↓

收集Bad Case

↓

分析原因

↓

修改Prompt

↓

离线测试

↓

AB测试

↓

上线


```

---

# 16.5.2 Bad Case分类

建立：

Bad Case库。


---

## 类型1：理解错误

例如：

用户：

> 帮我看看这个岗位。


AI：

直接修改简历。


原因：

Master Agent意图识别错误。


优化：

增加Intent规则。


---

## 类型2：内容质量低

例如：

JD分析过于通用。


原因：

缺少岗位Context。


优化：

Prompt增加：

岗位能力模型。


---

## 类型3：幻觉

例如：

简历增加不存在的数据。


原因：

约束不足。


优化：

增加真实性检查。


---

# 16.5.3 Prompt版本管理

每次修改保存版本。


例如：

```text id="op008"

Agent:

Resume Agent


Version:

v1.3


修改：

增加STAR限制


效果：

幻觉率下降20%

```

# 16.6.2 模型选择策略

不同任务使用不同模型。

## 复杂任务

使用强模型。


场景：

- JD深度分析；

## 简单任务

使用轻模型。


场景：

- 信息分类；
- 标签提取；
- Memory抽取。


---

目标：

保证体验，同时降低成本。
