# 职小伴 · 关键决策一页纸

> 面试口述用。产品无登录；差异化靠 Memory + Multi-Agent + Evaluation。

## 1. 为什么 Multi-Agent，而不是一个大 Prompt？

| 维度 | 单 Prompt | Multi-Agent（职小伴） |
|------|-----------|------------------------|
| 约束 | 简历防幻觉 vs 面试追问易互相干扰 | 分 Agent 独立红线与评测 |
| 可追责 | 难定位失败层 | 可归因到路由/生成/质检 |
| 成本 | 单次可能更短 | 多步更贵，但事故率更可控 |

取舍：接受更高时延，换可评测与可治理。时延通过 Thinking 面板与语音阶段文案管理预期。

## 2. 为什么不做生产微调 / LoRA？

求职事实高度个性化、更新频繁；核心问题是「这个用户有没有某段经历」，不是通用文风。落点：**Prompt + Memory 注入 + Evaluation 闸门**。

## 3. 为什么 RAG 主路径后置？

主路径用结构化简历/JD + Career Memory。pgvector/Embedding **预留**。先把记忆与防幻觉做硬，再扩检索，避免半成品「假 RAG」。

## 4. 为什么不做登录？

作品集演示优先：降低启动摩擦。用访客画像 +「清空画像」支持干净演示；不伪装成已上线账号体系。

## 5. 北极星（作品集口径）

1. 高风险虚构拦截有效率（精标负样本）
2. 主闭环可演示完成（VERIFY 差异化硬门槛）
