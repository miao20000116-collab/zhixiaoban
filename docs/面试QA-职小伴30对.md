# 职小伴 · AI 产品经理面试 QA（30 对）

> 面向面试官追问本项目。答案按可口述口径写，锚定仓库真实设计（Multi-Agent / Memory / Evaluation / 作品集验证指标）。姓名可用 XXX 替换。

---

### Q1. 用一分钟介绍职小伴这个项目？

**A：** 职小伴是我从 0 到 1 做的 AI 求职助手作品集项目。定位不是 ChatGPT 套壳，而是用 **Master 意图路由 + 多专业 Agent**（简历、JD、面试、职业咨询、Gap、推荐）+ **Career Memory 长期画像** + **Evaluation 真实性门禁**，覆盖「理解用户 → 分析岗位 → 优化材料 → 模拟面试 → 给可解释下一步」的闭环。北极星是 **真实可投递、路由准确、建议可解释**，不是堆功能按钮。

---

### Q2. 和直接用 ChatGPT 改简历有什么本质区别？

**A：** 三点。第一，**有记忆**：跨对话记住经历、目标、甚至「没有真实 RAG 经验」这类否定约束。第二，**有分工**：Master 路由到专业 Agent，而不是一个万能 Prompt 包办。第三，**有质检**：简历/复盘重要输出过 Evaluation，高风险虚构会阻断，避免帮用户「美化到穿帮」。

---

### Q3. 你在项目里具体负责什么？

**A：** 唯一产品经理视角，独立负责：痛点与定位、闭环与优先级、Agent 职责与意图体系、Prompt 产品规格、Memory/Task 规则、Evaluation 与精标集、验收与演示口径。工程实现可协作，但我能讲清规格、评测和取舍，并用质量报告验收。

---

### Q4. 用户痛点是怎么定义的？

**A：** 不是「文案不够漂亮」，而是：① 通用模型无长期记忆；② 简历优化易虚构；③ JD、简历、面试割裂，没有主线。模糊诉求像「帮我找工作」「想转 AI 产品」，需要 PM 拆成可落地闭环，而不是直接空聊适不适合。

---

### Q5. 为什么用 Multi-Agent，而不是一个大 Prompt？

**A：** 求职链路阶段不同、约束不同：改简历要防幻觉，面试要状态机追问，Gap 要 evidence，推荐要 sources。单 Prompt 难维护、难评测、难追责。拆成独立 Agent + 外置 `prompt.md`，Master 只做路由，Evaluation 横切质检，才符合可迭代的 AI 产品结构。

---

### Q6. 有哪些 Agent？各自干什么？

**A：** 共 9 个：Master（意图路由）；Memory（提取职业事实/约束）；Resume（解析/STAR/按 JD 定制）；Job（JD 分析）；Interview（模拟与复盘，含语音）；Career（咨询与基于事实的陪伴）；Career Gap（匹配差距，须 evidence）；Recommendation（带 why/sources 的行动计划）；Evaluation（内部质检，不对用户直接说话）。专业 Agent 禁止互调，必须经 Master。

---

### Q7. 意图体系怎么设计的？

**A：** 六类：`memory_update` / `resume` / `jd_analysis` / `interview` / `career_consult` / `general_chat`。特殊规则：补充/纠正/「没有真实…经验」优先 memory_update；焦虑被拒走 career_consult；只有明确优化/改简历才走 resume。有 Task 时优先推进下一步，但不覆盖用户明确新意图。低置信或复合需求会澄清拆步。

---

### Q8. 用户说「我想转 AI 产品，你帮我弄一下」怎么处理？

**A：** 这是模糊多意图，可能同时像咨询、Gap、JD、简历、面试。产品策略是 **澄清 + 分步**：先要目标岗/JD 和材料，再分析与优化，最后面试；并用 Task Memory 记下长期目标与下一步，避免一次乱路由或空谈「适不适合」。

---

### Q9. Career Memory 和聊天记录有什么区别？

**A：** 聊天记录是「聊了什么」；Career Memory 是结构化长期画像（经历、技能、目标、gap、progress，以及否定性约束）。多窗口对话独立，但 Memory 跨窗口共享。另外还有 Task Memory：记「正在完成什么、进度、下一步」，不只是摘要。

---

### Q10. 为什么强调「否定性事实」？

**A：** 求职场景最怕把「只上过 RAG 课」写成「丰富 RAG 落地」。否定约束必须入库并注入后续 Agent，否则 Resume/Gap 会重新造经验，Evaluation 再拦也滞后。Master 规则里这类话术优先走 memory_update，而不是改简历。

---

### Q11. Evaluation 怎么做？高风险时用户看到什么？

**A：** Evaluation 是横切质检：真实性、来源一致性、岗位匹配、风险分级。分档区分「润色/合理归纳」与「事实新增」。**high**（虚构项目/指标/职责升级）→ 阻断可投递结果，给问题列表；**medium** → 警告可编辑；**low** → 正常展示。精标集覆盖「提升 300%」、虚构公司、Gap 假优势等。

---

### Q12. 为什么不做生产环境微调 / LoRA？

**A：** 求职事实高度个性化、更新频繁；需要可解释和可审计；迭代要快。微调解决不了「这个用户到底有没有 RAG 项目」——那是 Memory + Evaluation 的事。对比：智能门诊曾实验 LoRA 但未上生产；科研 Agent 格式稳定适合 LoRA；职小伴落在 Prompt + Memory 注入 + 质检门禁。

---

### Q13. 你们做 RAG 了吗？为什么主路径不强调向量检索？

**A：** 架构预留了 PostgreSQL + pgvector 和 Embedding 配置，但 **业务主路径未强依赖 Embedding**。主路径是结构化材料（简历/JD）+ Career Memory 注入。这是阶段取舍：先把记忆与防幻觉做硬，再扩检索；不是忘了做。对外诚实讲「预留能力」，避免假 RAG 叙事。

---

### Q14. 北极星指标是什么？怎么算？

**A：** 作品集口径双北极星：① **高风险虚构拦截有效率**（应拦精标负样本被正确标 high/阻断）；② **主闭环可演示完成**（JD→Gap→简历含阻断→面试入口按演示脚本过关）。不伪装线上 DAU。模型层用各 Agent 质量报告（如 Master 8/8、Resume 8/8）做过程指标。

---

### Q15. 质量报告里有没有翻车？你怎么看？

**A：** 有。Memory 历史套件曾 **0/7**（经历补充被路由成索要简历），与「Memory 是差异化」冲突——必须主动讲，并补验收规格、修启发式路由、VERIFY 硬门槛。Job/Interview/Recommendation 也曾解析失败，已用规则兜底，避免「解析失败」甩给用户。面试加分点是诚实 + 治理，不是只报喜。

---

### Q16. 精标集 / 测试集怎么设计？

**A：** 按场景分库：`resume_hallucination`、`jd_analysis`、`interview_answer`、`career_gap`。含正负样本：虚构要 high，合理归纳勿误杀，空 Gap 暂不评分。评测集用于回归发版，不拿去教模型继续编。样本量曾偏少，按失败模式扩容是 P0。

---

### Q17. BadCase 怎么归因？

**A：** 不笼统归「模型幻觉」。标签包括：路由错误、Memory 漏写、幻觉、Eval 误伤、解析失败、缺 evidence、材料解析等。固定逆向顺序：用户表述 → 意图/Task → Memory/材料注入 → Agent Prompt → Evaluation → 前端展示。关闭前必须沉淀回归用例。

---

### Q18. Chat First 是什么？为什么还要 JD/简历按钮？

**A：** Chat First 指用户自然语言表达需求，不以功能菜单墙为主导航。JD/简历/语音面试是辅助入口，降低上传成本，但主路径仍是对话理解 + 路由，不是工具站。

---

### Q19. 语音面试怎么做的？有什么限制？

**A：** 电话式一对一：自动开麦、停顿提交、可打断，通话内展示面试官提问。ASR/TTS 与文本 LLM **配置分离**（避免打到无音频能力的 Base）。已知限制：非真流式 WebSocket，当前是「说完→转写→LLM→TTS」，延迟可感知——产品上用交互设计兜体验，技术上列为后置。

---

### Q20. Career Gap 和 Recommendation 如何保证「有依据」？

**A：** Gap 的优势/缺口必须带 evidence，引用 Memory 或 JD；信息不足显示「暂不评分」，不盲目高分。Recommendation 每条必须 why + sources + priority，禁止「保证拿 offer」；无来源或空对象由 Evaluation/结构校验降级或兜底计划。

---

### Q21. Task Memory 解决什么问题？

**A：** 长求职任务跨多天、多窗口，模型容易忘「正在准备字节 AI 产品面试」。Task Memory 外置目标、进度、下一步；Master 路由时读取；跨 Conversation 保持 active Task。侧栏 Current Task + Profile Career Progress 让用户看见主线，而不只是聊天摘要。

---

### Q22. 需求优先级怎么排？

**A：** **先防幻觉底线 → 主闭环跑通 → Chat First 体验**。真流式语音、强 RAG 进 Later。原则是 AI 产品里「帮用户造假履历」是事故，体验彩蛋不能插队过质量门禁。

---

### Q23. 遇到过交付/质量矛盾吗？怎么处理？

**A：** 用 STAR：情境是质量套件暴露解析/Memory 等问题但演示节点临近；任务是保证防幻觉 + 主闭环可讲；行动是规则兜底、分阶段演示路径、BadCase 日清并写进未通过清单；结果是主叙事可演示，缺陷有归因 backlog，不装作没有。

---

### Q24. Prompt 怎么管理？

**A：** Prompt 是产品规格的一部分，外置在各 Agent `prompt.md`，禁止写死在 chat 接口。每个 Agent 明确角色、边界、输出 schema、负面示例。改 Prompt 必须跑对应质量套件/精标集回归。有 Prompt 规格总表关联红线与评测。

---

### Q25. 如果简历原文很弱，模型想「帮写好看」怎么办？

**A：** 产品红线：宁可阻断或标 missing_information，不可无依据扩写。Evaluation 会打高风险；Resume Prompt 禁止补造公司/指标/技术栈。可引导用户补充真实材料，而不是替他虚构。

---

### Q26. 技术栈怎么选的？你为什么懂这些？

**A：** 前端 Next.js；后端 FastAPI；库 PostgreSQL（含 pgvector 预留）；LLM 走 OpenAI 兼容抽象层便于换模型。作为 AI PM，我需要懂到能做选型对比、写清约束、验收效果；不把自己定位成只写 PRD 不碰评测的人。作品集里我也用 vibe coding 快速验证方案。

---

### Q27. 这个项目最大的难点是什么？

**A：** 两个。一是 **模糊意图导致 Agent 调度乱**——用澄清链、Task 续写、复合指令拆步解决。二是 **简历/复盘幻觉**——用 Evaluation 阻断 + 精标集守住真实可投递。另外 Memory 曾验收翻车，说明差异化能力必须有门禁，不能只写在定位里。

---

### Q28. 如果让你做下一期，优先做什么？

**A：** 按优先级：Memory live 套件稳过并守住 VERIFY 硬门槛；精标集继续按 BadCase 扩容；Eval 误伤治理；再考虑体验态集中规格。真流式语音和强 RAG 明确后置，有场景和评测再上，避免半成品。

---

### Q29. 你如何证明这不是 Demo 玩具？

**A：** 有完整闭环与 Phase 路线；Agent/Prompt/评测/Dashboard 可演示；VERIFY 含差异化硬门槛（Memory 约束、防虚构阻断、Gap evidence）；质量报告与精标集可复现。同时诚实承认作品集验证口径与已知限制（非真流式、RAG 未强依赖），这比吹线上 DAU 更可信。

---

### Q30. 你从这个项目沉淀了什么 AI 产品方法论？

**A：** 四条。① 先定义伤害面（虚构履历）再堆能力；② 多智能体要路由清晰、职责可评测；③ 记忆与质检是差异化，必须进验收硬门槛；④ 指标分业务/体验/模型三层，发版靠精标集与 BadCase 闭环。这套方法在医疗客服、科研 Agent 和职小伴是同一套「规格—评测—归因」打法。
